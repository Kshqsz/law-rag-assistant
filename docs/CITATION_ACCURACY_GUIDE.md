# 法律引用准确率分析脚本使用指南

## 📊 脚本功能

这个脚本用来评估系统生成的答案中，**法律引用的准确性**。它会：

1. **读取所有AI回答**：从数据库中提取所有包含`law_context`的对话
2. **提取答案中的法律条文**：用正则表达式找出所有《法律名》、第XX条等引用
3. **在law_context中验证**：检查这些引用是否真实存在于提供的法律依据中
4. **生成准确率报告**：输出JSON、文本和CSV格式的详细分析

## 🚀 快速使用

### 1. 分析最近5条对话（测试用）

```bash
python scripts/analyze_citation_accuracy.py --limit 5
```

**输出示例**：

## 🔍 理解准确率

### 准确率的含义

```
准确率 = 已验证的引用数 / 总引用数

例如：
- 如果答案引用了《刑法》第233条
- 且这个引用确实出现在law_context中
- 则该引用被视为"已验证" ✓

- 如果答案引用了《道交法》
- 但law_context中找不到这个法律的任何内容
- 则该引用被视为"未验证" ✗（可能是虚构）
```

### 准确率评级

| 准确率范围 | 评级 | 含义 |
|-----------|-----|------|
| ≥ 95% | 🌟 优秀 | 虚构风险 < 5% |
| ≥ 85% | ⭐ 良好 | 虚构风险 < 15% |
| ≥ 70% | 👍 一般 | 虚构风险 < 30% |
| < 70% | ⚠️ 需改进 | 虚构风险 > 30% |

## 🔧 诊断和改进

### 准确率低的原因分析

#### 原因1: 检索失败
**症状**：答案在没有法律依据的情况下创建了引用
```
law_context: "关于交通事故的内容..."
answer: "根据《道交法》第50条..."
        但law_context中没有《道交法》的内容
```

**解决方案**：
- 检查向量库中是否有道路交通法的数据
- 运行 `python scripts/build_vector_db.py` 重建索引

#### 原因2: 提示词鼓励虚构
**症状**：答案中有与检索结果不匹配的引用
```
law_context:
  - 刑法第233条：过失致人死亡...
answer:
  - 刑法第233条（✓ ok）
  - 《道交法》第50条（✗ 虚构！）
```

**解决方案**：
- 在 `law_ai/prompt.py` 中强化拒答机制：
  ```python
  "【禁止虚构原则】
   1. 只使用提供的法律依据回答
   2. 如果无法从law_context中找到依据，必须说明
   3. 禁止生成'据我了解...'这样的说法"
  ```

#### 原因3: 答案使用了简称或别名
**症状**：答案用简称，但law_context用全称（脚本已部分解决）
```
answer: "根据《民法典》..."
law_context: "《中华人民共和国民法典》..."
```

**解决方案**：脚本已包含别名处理（见LAW_ALIASES字典）

## 🚨 常见问题

### Q: 为什么有些法律引用被标记为"未验证"？

A: 脚本检查引用是否出现在`law_context`中。如果答案引用了法律但`law_context`中没有这个法律的内容，就会被标记为未验证。这通常表示：
1. **虚构**：模型凭记忆生成（需要修复）
2. **检索失败**：向量库中没有这个法律（需要添加数据）

### Q: JSON报告中为什么有些字段为空？

A: 这是**正常的**。脚本会：
- 仅保留前50条对话的详细结果（节省文件大小）
- 仅保留每条对话的前3条未验证引用

### Q: 能否修改脚本来改进检测？

A: 完全可以！脚本是模块化设计：
- `CitationExtractor`：修改的正则模式来改进引用提取
- `CitationValidator`：修改验证逻辑
- `AccuracyReportGenerator`：修改报告格式
