## 6.1 系统实现基础

### 6.1.1 开发环境与技术栈

系统采用前后端分离架构，核心技术栈如下：

```python
@router.post("/register", response_model=UserResponse)
async def register(user_data: UserCreate, db: Session = Depends(get_db)):
    existing_user = get_user_by_username(db, user_data.username)
    if existing_user:
        raise HTTPException(status_code=400, detail="用户名已被注册")
    user = create_user(db, user_data.username, user_data.password)
    return user

@router.post("/login", response_model=Token)
async def login(form_data: OAuth2PasswordRequestForm = Depends(), db: Session = Depends(get_db)):
    user = authenticate_user(db, form_data.username, form_data.password)
    if not user:
        raise HTTPException(status_code=401, detail="用户名或密码错误")
    access_token = create_access_token(data={"sub": user.username, "user_id": user.id})
    return {"access_token": access_token, "token_type": "bearer"}
```

```python
# backend/auth.py
def get_password_hash(password: str) -> str:
    salt = bcrypt.gensalt()
    return bcrypt.hashpw(password.encode('utf-8'), salt).decode('utf-8')


def create_access_token(data: dict, expires_delta: Optional[timedelta] = None) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
```

#### 代码解析

- 前端认证页通过双 Tab 复用同一页面，实现“注册-登录”流程闭环，降低页面切换成本。
- 后端 `register` 接口先查重再创建账户，避免用户名冲突；创建时调用 `get_password_hash`，不明文存储密码。
- 后端 `login` 接口通过 `authenticate_user` 验证账户密码后签发 JWT，返回 `access_token` 给前端。
- JWT 中包含 `sub` 和 `user_id`，后续请求通过 `Authorization: Bearer <token>` 访问受保护接口，实现统一身份鉴权。

#### 代码解析

- 第一阶段由 `RunnableMap` 并行触发两类检索：
  - `law_docs`：面向 Chroma 法律知识库的语义检索
  - `web_docs`：面向 DuckDuckGo 的实时网络检索
- 第二阶段将检索结果分别格式化为 `law_context` 与 `web_context`，用于后续提示词注入。
- 第三阶段调用 `log_prompt_and_call_llm` 完成最终生成，同时保留上下文，便于前端展示来源。
- `LoggingMultiQueryRetriever` 会自动将用户问题重写为多条检索子问题，可提升法律术语场景下的召回率与鲁棒性。

### 6.2.4 流式输出与会话持久化

#### 显示效果

用户发送问题后，AI 回答以“逐字流式”方式实时出现；回答结束后，对话自动保存到历史会话，刷新页面仍可继续上下文对话。

#### 核心代码

```python
# backend/routers/chat.py
@router.post("/stream", summary="流式发送消息")
async def chat_stream(...):
    async def generate():
        full_answer = ""
        law_ctx = ""
        web_ctx = ""

        async for chunk in law_qa_service.stream_answer(...):
            if isinstance(chunk, dict):
                law_ctx = chunk.get("law_context", "")
                web_ctx = chunk.get("web_context", "")
            else:
                full_answer += chunk
                yield f"data: {json.dumps({'token': chunk}, ensure_ascii=False)}\\n\\n"

        yield f"data: {json.dumps({'done': True, 'conversation_id': conversation_id, 'law_context': law_ctx, 'web_context': web_ctx}, ensure_ascii=False)}\\n\\n"

    return StreamingResponse(generate(), media_type="text/event-stream")
```

```javascript
// frontend-user/src/stores/chat.js
for await (const chunk of api.chatStream(enhancedQuestion, this.currentConversationId, documentId)) {
  if (chunk.token) {
    fullContent += chunk.token
    this.messages[aiMessageIndex].content = fullContent
  } else if (chunk.done) {
    lawContext = chunk.law_context || ''
    webContext = chunk.web_context || ''
  }
}
```

#### 代码解析

- 后端使用 `StreamingResponse + text/event-stream` 持续推送 token，前端无需等待整段回答完成。
- 流结束时发送 `done` 事件，携带 `conversation_id`、`law_context`、`web_context`，完成一次问答闭环。
- 前端 `Pinia` 中维护 `messages` 状态，实现“边接收边渲染”；接收 `done` 后将上下文附着到本条 assistant 消息。
- 后端在流完成后将问答写入 `messages` 表，确保历史可追溯、可复现。

```python
# law_ai/chain.py
def enhance_search_with_document(x):
    search_q = x.get("search_question", x["question"])
    doc_content = x.get("uploaded_document")
    if doc_content:
        rewritten_q = rewrite_chain.invoke({
            "doc_preview": doc_preview,
            "question": search_q
        }).strip()
        return rewritten_q
    return search_q
```

#### 代码解析

- 上传接口先进行扩展名校验和体积校验，防止异常文件进入业务链路。
- `enhance_search_with_document` 在有文档时对检索问题进行语义重写：
  - 输入：用户问题 + 文档摘要
  - 输出：更精确的法律检索 query
- 该机制可将“宽泛表达”映射为“可检索表达”，有效提高文档场景下法律条文命中率。

```python
    total_users = db.query(User).count()
```
