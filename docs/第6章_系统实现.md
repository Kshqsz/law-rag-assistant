# 第6章 系统实现

本章在第5章系统设计的基础上，面向工程落地过程，重点说明系统关键功能的实现方式。围绕“用户可见效果 - 核心代码 - 技术解析”的主线，展示本系统如何将 RAG 法律问答能力、流式交互能力和后台统计能力转化为可用产品。

## 6.1 系统实现基础

### 6.1.1 开发环境与技术栈

系统采用前后端分离架构，核心技术栈如下：

- 后端：Python 3.11、FastAPI、SQLAlchemy、LangChain
- 前端：Vue 3、Vite、Element Plus、Pinia、ECharts
- 数据层：SQLite（业务数据）+ ChromaDB（向量数据）
- 模型层：Qwen（生成模型）+ text-embedding-v2（嵌入模型）

用户输入法律问题后，系统返回结构化回答，并同时展示“法律依据”和“网络来源”折叠面板。该交互效果体现了“答案 + 证据”的可解释输出模式。

```python
# law_ai/chain.py
chain = (
    RunnableMap(
        {
            "law_docs": lambda x: multi_query_retriver.invoke(enhance_search_with_document(x)),
            "web_docs": lambda x: web_retriever.invoke(enhance_search_with_document(x)),

            "question": lambda x: x["question"],
            "history": lambda x: x.get("history"),
            "uploaded_document": lambda x: x.get("uploaded_document")
        }
    )
    | RunnableMap({
        "answer": log_prompt_and_call_llm,
        "law_context": lambda x: x["law_context"],
        "web_context": lambda x: x["web_context"]
    })
)
```

```python
# law_ai/retriever.py
retriever = LoggingMultiQueryRetriever(
    retriever=retriever,
    llm_chain=llm_chain,
    parser_key="lines"
)
```

#### 代码解析

- 第一阶段由 `RunnableMap` 并行触发两类检索：
  - `law_docs`：面向 Chroma 法律知识库的语义检索
  - `web_docs`：面向 DuckDuckGo 的实时网络检索
- 第二阶段将检索结果分别格式化为 `law_context` 与 `web_context`，用于后续提示词注入。
- 第三阶段调用 `log_prompt_and_call_llm` 完成最终生成，同时保留上下文，便于前端展示来源。
- `LoggingMultiQueryRetriever` 会自动将用户问题重写为多条检索子问题，可提升法律术语场景下的召回率与鲁棒性。

### 6.2.2 流式输出与会话持久化

#### 显示效果

用户发送问题后，AI 回答以“逐字流式”方式实时出现；回答结束后，对话自动保存到历史会话，刷新页面仍可继续上下文对话。

![图6-2 流式回答与历史会话（待替换）](./image/chapter6/fig6-2-stream-chat.png)

图6-2 流式回答与历史会话

#### 核心代码

```python
# backend/routers/chat.py
@router.post("/stream", summary="流式发送消息")
async def chat_stream(...):
    async def generate():
        full_answer = ""
        law_ctx = ""
        web_ctx = ""

        async for chunk in law_qa_service.stream_answer(...):
            if isinstance(chunk, dict):
                law_ctx = chunk.get("law_context", "")
                web_ctx = chunk.get("web_context", "")
            else:
                full_answer += chunk
                yield f"data: {json.dumps({'token': chunk}, ensure_ascii=False)}\\n\\n"

        yield f"data: {json.dumps({'done': True, 'conversation_id': conversation_id, 'law_context': law_ctx, 'web_context': web_ctx}, ensure_ascii=False)}\\n\\n"

    return StreamingResponse(generate(), media_type="text/event-stream")
```

```javascript
// frontend-user/src/stores/chat.js
for await (const chunk of api.chatStream(enhancedQuestion, this.currentConversationId, documentId)) {
  if (chunk.token) {
    fullContent += chunk.token
    this.messages[aiMessageIndex].content = fullContent
  } else if (chunk.done) {
    lawContext = chunk.law_context || ''
    webContext = chunk.web_context || ''
  }
}
```

#### 代码解析

- 后端使用 `StreamingResponse + text/event-stream` 持续推送 token，前端无需等待整段回答完成。
- 流结束时发送 `done` 事件，携带 `conversation_id`、`law_context`、`web_context`，完成一次问答闭环。
- 前端 `Pinia` 中维护 `messages` 状态，实现“边接收边渲染”；接收 `done` 后将上下文附着到本条 assistant 消息。
- 后端在流完成后将问答写入 `messages` 表，确保历史可追溯、可复现。

```python
# backend/routers/documents.py
ALLOWED_EXTENSIONS = {".txt", ".md", ".pdf", ".doc", ".docx"}
MAX_FILE_SIZE = 10 * 1024 * 1024

@router.post("/upload")
async def upload_document(file: UploadFile = File(...), ...):
    validate_file(file)
    content = await file.read()
    if len(content) > MAX_FILE_SIZE:
        raise HTTPException(status_code=400, detail="文件大小超过限制")
```

```python
# law_ai/chain.py
def enhance_search_with_document(x):
    search_q = x.get("search_question", x["question"])
    doc_content = x.get("uploaded_document")
    if doc_content:
        rewritten_q = rewrite_chain.invoke({
            "doc_preview": doc_preview,
            "question": search_q
        }).strip()
        return rewritten_q
    return search_q
```

#### 代码解析

- 上传接口先进行扩展名校验和体积校验，防止异常文件进入业务链路。
- `enhance_search_with_document` 在有文档时对检索问题进行语义重写：
  - 输入：用户问题 + 文档摘要
  - 输出：更精确的法律检索 query
- 该机制可将“宽泛表达”映射为“可检索表达”，有效提高文档场景下法律条文命中率。

# backend/routers/admin.py
@router.get("/stats", response_model=AdminStatsResponse)
async def get_admin_stats(...):
    total_users = db.query(User).count()
    total_conversations = db.query(Conversation).count()
    total_messages = db.query(Message).count()

    total_tokens = db.query(func.coalesce(func.sum(TokenUsage.total_tokens), 0)).scalar()
    today_tokens = db.query(func.coalesce(func.sum(TokenUsage.total_tokens), 0)).filter(
        func.date(TokenUsage.created_at) == today_str
    ).scalar()

    return {
        "total_users": total_users,
        "total_conversations": total_conversations,
        "total_messages": total_messages,
        "total_tokens": total_tokens,
        "today_tokens": today_tokens,
        ...
    }
