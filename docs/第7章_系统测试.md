# 第7章 系统测试与效果评估

本章基于项目现有测试脚本、评测工具与历史评测结果，对系统进行功能测试、效果评估与性能分析。测试重点围绕“功能可用性、回答质量、引用可信度、响应效率与工程稳定性”展开。

## 7.1 测试方案设计

### 7.1.1 测试目标

系统测试目标如下：

1. 验证核心业务功能是否完整可用（登录注册、对话、收藏导出、后台统计等）。
2. 评估 RAG 链路相对于非 RAG 基线模型的回答质量提升幅度。
3. 评估回答中法律引用的可验证性，量化“幻觉风险”。
4. 观察系统在批量问答任务下的平均时延与稳定性。

### 7.1.2 测试环境

- 操作系统：macOS（本地开发环境）
- Python 版本：3.11
- 后端框架：FastAPI + SQLAlchemy
- 前端框架：Vue3 + Element Plus
- 数据库：SQLite + ChromaDB
- 模型：Qwen 系列（`qwen-plus`）

### 7.1.3 测试数据与工具

1. 功能测试脚本：
   - `tests/test_law_related_check.py`
   - `tests/test_question_rewrite.py`
   - `tests/test_continuous_chat.py`
   - `tests/test_document_search.py`
2. A/B 评测脚本：`scripts/evaluate_rag_vs_base.py`
3. 法律引用准确率脚本：`scripts/analyze_citation_accuracy.py`
4. 收藏与导出联调模块：`backend/routers/favorites.py`、`frontend-user/src/views/Layout.vue`
5. A/B 数据集：`tests/ab_eval_dataset.sample.jsonl`（50 条样本）
6. 评测输出目录：`evaluation_results/`

### 7.1.4 测试执行命令

```bash
# 1) 功能测试（示例）
python tests/test_law_related_check.py
python tests/test_question_rewrite.py
python tests/test_continuous_chat.py

# 1.1) 收藏/导出功能联调验证（示例）
# 收藏：在对话页面对消息执行“收藏”，检查收藏列表与去重提示
# 导出：在历史会话执行“导出PDF”，检查PDF生成与内容完整性

# 2) A/B 对比评测（RAG vs Baseline）
python scripts/evaluate_rag_vs_base.py \
  --dataset tests/ab_eval_dataset.sample.jsonl \
  --output-dir evaluation_results \
  --model-name qwen-plus \
  --limit 0

# 3) 法律引用准确率评测
python scripts/analyze_citation_accuracy.py --limit 0
```

## 7.3 效果评估（检索增强与基础回答对比）

### 7.3.1 测试说明

本节采用同一批 50 个法律问题，对两种回答方式进行对照测试：一组仅使用模型直接回答（Baseline），另一组在回答前引入检索增强（RAG）。两组使用相同模型、相同问题集合和统一评分口径，重点观察四个方面：回答质量是否提升、法律依据是否更充分、响应速度是否可接受、输出内容长度是否可控。为避免单一评分偏差，本节同时使用自动评分、专家模型评分与综合评分，并结合逐题对比结果进行分析。

评分执行方式如下：自动评分由评测程序按统一规则自动计算；专家模型评分由独立评审模型 Qwen3.5-plus 完成；综合评分由系统将规则评分、专家模型评分和成对比较评分进行加权融合后得到。

### 7.3.2 核心指标结果

| 指标 | Baseline（直接回答） | RAG（检索增强） | 差值（RAG-Baseline） |
|---|---:|---:|---:|
| 平均自动评分 | 33.28 | 55.94 | +22.66 |
| 平均综合评分 | 59.10 | 73.71 | +14.61 |
| 平均专家模型评分 | 89.76 | 93.10 | +3.34 |
| 平均时延（ms） | 27511.72 | 28668.23 | +1156.51 |
| 成本代理（平均输出字符） | 1773.64 | 1492.26 | -281.38 |

从总体结果看，检索增强方案在三类质量指标上均优于直接回答方案，尤其在综合评分上提升明显，说明其在法律问答场景中的稳定增益较强；与此同时，检索增强带来约 1.16 秒的平均时延增加，体现出“质量提升与响应速度”之间的工程权衡。

其中，三个核心质量指标的含义如下：

1. 平均自动评分：指每道题由规则引擎自动打分后的平均值，主要依据关键词命中、法律名称命中、引用与证据一致性、回答与证据贴合度、是否拒答等客观信号。
2. 平均综合评分：指每道题的最终得分平均值，该最终得分由规则评分、专家模型评分、成对比较评分加权融合得到，用于反映整体答复质量。
3. 平均专家模型评分：指独立评审模型对每道题进行专业评议后的平均值，重点考察内容相关性、事实与法律真实性、答非所问程度以及法律引用质量。

## 7.4 法律引用准确率评估

### 7.4.1 测试说明

本节用于评估系统回答中法律引用的可追溯性与可信度。测试对象为评测过程中产生的 AI 回答消息，测试流程分为三个步骤：首先从回答文本中抽取法律名称与条文引用；其次在该回答对应的检索证据中进行逐条回查，判断该引用是否可被证据支持；最后汇总统计总引用数、已验证引用数、未验证引用数，并计算整体准确率。准确率计算方式为：$引用准确率 = \frac{已验证引用数}{总引用数} \times 100\%$。

### 7.4.2 测试结果

最新一轮测试结果如下：

| 指标 | 数值 |
|---|---:|
| 分析 AI 消息数 | 95 |
| 总引用数 | 1125 |
| 已验证引用数 | 1070 |
| 未验证引用数 | 55 |
| 总体准确率 | 92.9% |

多轮测试结果如下：

| 评测批次 | 样本规模（AI消息） | 引用准确率 |
|---|---:|---:|
| 第1轮 | 110 | 89.6% |
| 第2轮 | 10 | 99.2% |
| 第3轮 | 95 | 92.9% |

### 7.4.3 结果分析

1. 引用准确率达到 92.9%，说明系统输出的大部分法律引用可在检索证据中复核。
2. 未验证引用占比约 7.1%，仍存在进一步优化空间（如提示词约束与检索覆盖增强）。
3. 从多轮结果看，在中大样本规模（95~110）下，引用准确率稳定在 89.6%~92.9% 区间，说明系统在法律引用可信度方面具有较好的稳定性。
4. 结合前述回答质量对比可见，检索增强不仅提升了回答效果，也增强了法律依据的可解释性，但后续仍可针对未验证引用继续优化检索覆盖与答案约束。

## 7.6 本章小结

本章完成了系统的功能测试与效果评估。结果表明：

1. 系统核心功能完整可用，测试脚本覆盖法律问答主链路。
